# Слоты

Слот = поток работ + своя ветка + свой файл `context/<слот>.md`.

🔴 **Главное правило: сверять ветку ПЕРЕД КАЖДЫМ коммитом** (`git branch --show-current`).
Если слоты делят одну рабочую копию, сосед может переключить ветку под тобой.

⚠️ **Пиши только в свой `context/`.** Надо передать факт соседу — пиши в `topics/`
(это общее знание). Чужие оперативные файлы не редактируются.

## Ветки и GitHub — решение владельца 18.08

**GitHub — основное место, где лежит код.** Локальная копия рабочая, не хранилище.

Поток на каждый осмысленный шаг:

```
git checkout -b step/<фаза>-<что>  →  коммит  →  push  →  gh pr create  →  владелец смотрит  →  мерж в main
```

`main` всегда актуален, мимо глаз владельца код не проезжает. Долгоживущих веток нет.
**Мемори-банк — исключение:** коммитится прямо в `main`, память проекта общая
и не должна жить в ветке шага.

Авто-пуша нет: все четыре хука в `.git/hooks` — штатные Git LFS. Уезжает только явным
`git push`. `gh` авторизован как `toycenterboss-bot`, права `repo` и `workflow`.

⚠️ **Репозиторий публичный, и это осознанно:** он служит каналом передачи разработки
в закрытый контур МГТС. Закроется после передачи. Следствие, которое не отменяется:
всё, что здесь лежало, считается прочитанным посторонними — куки вынесены (PR #1),
токены и пароль из истории надо отзывать у провайдеров (B-01).

Из репозитория намеренно исключены: `backups/`, `strapi-backups/`, `mgts-backend/.tmp/`
(живая база SQLite) и `.env*`. Дампы, база и секреты на GitHub не уезжают.

## Когда заводить второй слот
Когда появится второй параллельный поток работ. Тогда же:
`git worktree add ../runs-<слот> <ветка>` — это правильный способ, дисциплина сверки хуже.
