# Валидация 118 существующих страниц против новой структуры

Дата: 17.08.2026 | Статус: результат замера

Источник списка — `docs/project/visual-compare/report.json`: реальный прогон **118 страниц**
из Strapi. Не оценка «на глаз», а фактический перечень URL, которые сейчас отдаёт сайт.
Колонка «% расхождения» — попиксельная разница React-версии со статикой из того же прогона.

## 1. Что снимаем — и это единственное болезненное решение

13 страниц раздела «Бизнесу»: доступ в интернет, цифровое ТВ, мобильная связь, телефония,
настройка оборудования, компьютерная помощь, способы оплаты, видеонаблюдение для офиса,
охранная сигнализация, все услуги, виртуальная АТС, акции.

По стратегии 2027–2029 это **не продуктовая линейка МГТС**: сервисы связи продаёт МТС.
Три варианта:

1. **Снять с публикации**, поставить редиректы на соответствующие страницы МТС Бизнес.
   Честно, но теряется поисковый трафик, который на них идёт годами.
2. **Оставить страницы-заглушки** с одним экраном и переходом. Трафик сохраняется,
   пользователь не упирается в 404.
3. Оставить как есть до отдельного решения.

Моё предложение — второй вариант: он сохраняет SEO и при этом не притворяется,
что МГТС продаёт мобильную связь. **Но это решение владельцев, не дизайнера.**

⚠️ Перед любым из вариантов нужно посмотреть трафик на эти 13 страниц. Аналитики на сайте
нет вообще (ни Метрики, ни Matomo — `grep` даёт ноль), так что сначала счётчик, потом решение.

То есть **самое денежное направление на сайте не представлено вообще**. Это, пожалуй,
важнее любого визуала.

## 3. Где сайт уже совпадает со стратегией — и это приятно

- **`/government/*` — 20 страниц, крупнейший раздел сайта.** По стратегии «Город» —
  ключевая клиентская группа. Раздел готов, нужно только переименовать вывеску
  с «Госзаказчикам» на «Городу» и добавить карту.
- **`/operators/*` — 11 страниц**, включая присоединение, передачу данных, ЛКС,
  размещение на площадках, недискриминационный доступ. Ядро InfraTech уже описано.
- **`/developers/*` — 7 страниц**: подключение объектов (жилые, коммерческие, стройка),
  компенсация убытков, цифровые решения. Ядро PropTech на месте.
- **`/services/scenario-*` — 6 сценариев**: подключение объекта, связность данных,
  инфраструктура 360, сетевые операции, безопасный объект, видео и доступ.
  Это готовый мост между «кто вы» и «что вам нужно» — в макете он не задействован,
  а зря.

## 4. Что говорит колонка расхождений

Самые «сломанные» страницы по визуальному сравнению — ровно те, что и так переделываются:

| Страница | % | Комментарий |
|---|---:|---|
| `/search` | 34.6 | поиск не реализован, страница-заглушка |
| `/contact` | 32.1 | переделывается в контакт-хаб |
| `/career` | 25.0 | пересобирается в два трека |
| `/operators` | 24.7 | сегментный лендинг, новые блоки |
| `/cookie_processing` | 24.1 | 🔴 юридическая страница не должна расходиться на четверть |
| `/developers` | 23.4 | сегментный лендинг |
| `/operators/nondiscriminatory_access` | 23.1 | 🔴 регуляторная страница, расхождение недопустимо |
| `/` | 20.9 | пересобирается |

🔴 Два случая выбиваются: `cookie_processing` и `nondiscriminatory_access` — это
юридические и регуляторные тексты. Там расхождение означает, что часть контента
не доехала, и это надо чинить до, а не после редизайна.

## 5. Порядок действий

1. **Поставить счётчик** — без данных по трафику решение о 13 страницах «Бизнесу»
   принимать нельзя.
2. **Починить две регуляторные страницы** — расхождение 23–24 % на юридическом тексте
   это дефект, а не вопрос дизайна.
3. **Завести 3 продуктовые страницы InfraTech** — colocation, тёмная оптика, BigTech.
   Самый большой разрыв между стратегией и сайтом.
4. Переименовать «Госзаказчикам» → «Городу», не трогая 20 страниц внутри.
5. Дальше — по плану интеграции.
