## 1. Компонент «Карта Москвы» — `page.moscow-map`

### 1.1 Назначение и три режима

| Режим | Где | Что делает |
|---|---|---|
| `backdrop` | главная, сегментные лендинги | полноэкранная подложка героя, реагирует на наведение на карточки развилки |
| `section` | внутри раздела | блок в потоке страницы: карта + подпись, без интерактива или с подсветкой одного слоя |
| `cases` | PropTech, Город, InfraTech | интерактивная карта объектов с фильтрами и карточкой |

### 1.2 Данные

- Геометрия — **один источник на весь сайт**: `api::geo` (single type), ~80 КБ.
  Отдаётся отдельным запросом, кэш длинный, в бандл не попадает.
- Состав: контур города, анклавы (Зеленоград + 4), 129 границ районов, Москва-река, Яуза,
  узлы и рёбра условной схемы сети, справочник «район → центроид».
- Источник: OpenStreetMap, лицензия **ODbL** → на странице обязана быть атрибуция.
  **Q1.** Где размещаем: в подвале сайта один раз или подписью под каждой картой?

### 1.3 Обязательные ограничения

🔴 **Схема сети — условная, не трассировка ЛКС.** Это должно быть написано в интерфейсе,
а не только в коде. Иначе оператор примет картинку за карту ёмкости и придёт с вопросами.

🔴 **Адреса площадок не публикуются.** Поле `sitePrecision` по умолчанию `district`.
Переключение на `exact` — только с письменным согласием ИБ, и это видно в истории Strapi.

### 1.4 Поведение

- Наведение на карточку сегмента / клик по фильтру → подсветка слоя, остальное гаснет
  до 18 % (не до нуля — иначе карта «схлопывается»).
- Клавиатура: слои переключаются по `focus`, не только по `hover`.
- `prefers-reduced-motion` → анимация импульсов выключена, статика остаётся.
- Мобильный: `hover` не существует. **Q2.** На телефоне карта — статичная картинка
  без интерактива, или тап по точке открывает карточку? Моё предложение: в `backdrop`
  статика, в `cases` тап работает.

### 1.5 Производительность (бюджет)

| Показатель | Требование | Как проверяем |
|---|---|---|
| Вес геометрии | ≤ 100 КБ gzip, отдельным запросом | сеть в DevTools |
| Первый кадр | ≤ 150 мс после появления данных | performance mark |
| Кадры | ≥ 50 fps на ноутбуке без внешней видеокарты | счётчик в лаборатории |
| Влияние на LCP главной | 0 — карта грузится динамически, после гидратации | Lighthouse до/после |

Реализовано: статичные слои кэшируются в offscreen-canvas, перерисовка только при смене
состояния. Не реализовано: динамический импорт компонента (`next/dynamic`, `ssr:false`).

### 1.6 Доступность

- `<canvas aria-hidden="true">` + текстовая альтернатива рядом: карта декоративна,
  вся информация обязана дублироваться списком.
- В режиме `cases` список объектов слева — **основной** интерфейс, карта — вспомогательный.
  Это же решает мобильный и скринридер.

## 2. Точки на карте

### 2.1 Два независимых слоя

| Слой | Что | Источник | Публичность |
|---|---|---|---|
| Инфраструктура | 73 объекта сети, из них 40 площадок с электричеством | `api::geo.sites` | только маркерно, precision=district |
| Кейсы | реализованные объекты PropTech | `api::case` | район + название объекта |

### 2.2 Визуальный язык

| Тип | Форма | Когда подсвечивается |
|---|---|---|
| мини-ЦОД | квадрат | сегмент BigTech и ЦОД |
| технологическая площадка | ромб | сегмент Операторам |
| объект на базе АТС | круг | сегмент Операторам |
| кейс PropTech | круг с кольцом | всегда, если проходит фильтр |
| неподтверждённые данные | оранжевый пунктир вокруг | в проде не публикуются вовсе |

### 2.3 Правила размещения

- Координата берётся **из справочника районов**, а не из адреса. Точка ставится в центроид
  района с детерминированным разбросом, если объектов в районе несколько.
- **Q3.** Что делать, если в одном районе 5 кейсов? Кластер с числом или веер точек?
  Моё предложение: кластер, при клике — список.
- Точка без района не рендерится и попадает в отчёт валидации контента.

## 3. Карточка объекта

### 3.1 Состав и что обязательно

| Блок | Обязателен | Правило |
|---|---|---|
| Название объекта | да | без адреса и без номера дома |
| Тип, район, год, этажность | да | район из справочника |
| Фото до / монтаж / после | нет | рендерится только то, что загружено. Один слот — тоже валидно |
| 4 числовых факта | нет | каждый с `verified` и `source`; неподтверждённые в проде скрыты |
| Перечень систем | да | из фиксированного словаря: СКС, СКУД, СОТ, АПС, BMS, … |
| Отзыв клиента | нет | рендерится **только** при `quoteApproved: true` |
| Логотип клиента | нет | только при `clientLogoApproved: true` |
| 3D-разрез | нет | вкладка появляется, только если есть `floorPlan` |

### 3.2 Деградация — главное требование

Карточка обязана **выглядеть законченной при минимуме данных**: название, тип, район, год
и список систем. Всё остальное опционально. Иначе первые кейсы будут выглядеть дырявыми,
и раздел не запустится никогда.

### 3.3 Фотографии

- Формат: три состояния одного ракурса. **Если ракурсы разные — лучше два кадра, чем три.**
- **Q4.** Требование к съёмке: одна точка, один свет, одинаковый кроп. Есть ли у вас
  фотоархив, снятый так, или снимать заново? От этого зависит, запускаем ли блок «до/после»
  вообще или начинаем с «стало».
- Технически: 4:3, ≥ 1600 px по длинной стороне, WebP, ленивая загрузка, `alt` обязателен.

### 3.4 Открытие и URL

- **Q5.** Карточка — модалка без своего адреса или страница `/cases/<slug>`?
  Разница принципиальная: во втором случае кейсы индексируются, на них можно ссылаться
  из презентаций и КП, но нужен шаблон страницы и работа с SEO. Моё предложение:
  и то и другое — карточка открывается модалкой с подменой URL, прямая ссылка отдаёт страницу.

## 4. 3D-разрез этажей

### 4.1 Граница ответственности

**Мой прототип — это рамка и логика взаимодействия, а не графика.** Ваш существующий
рендер из соседней ветки встаёт на место канваса. Требования ниже — к тому, как он
должен встроиться.

### 4.2 Требования к встраиванию

| Требование | Значение |
|---|---|
| Формат | компонент, монтируемый в контейнер фиксированной пропорции 1 : 1,05 |
| Вход | `floorPlan` из `api::case` — этажи и перечень систем на каждом |
| Выход (события) | `floor:hover`, `floor:select`, `system:toggle` — чтобы карточка реагировала |
| Управление снаружи | фильтр систем живёт в карточке, а не внутри рендера |
| Загрузка | динамический импорт, только при открытии вкладки. На вес страницы не влияет |
| Fallback | нет `floorPlan` → вкладка не показывается; ошибка загрузки → статичная схема |
| Мобильный | **Q6.** Показываем вообще? Тяжёлый 3D на телефоне — спорно |

### 4.3 Что показывает

Этажи снизу вверх, на каждом — трассы включённых систем, вертикальные стояки между этажами.
Наведение на этаж подсвечивает его и его стояки. При большом числе этажей показывается
часть с подписью «показано N из M».

### 4.4 Вопросы к вашей ветке с 3D

- **Q7.** На чём сделан рендер — three.js, готовый вьюер, видео? От этого зависит вес
  и возможность динамической загрузки.
- **Q8.** Данные для него берутся из проектной документации или рисуются вручную?
  Если вручную — блок будет только у витринных кейсов, и это нормально, но надо решить сразу.
- **Q9.** Есть ли ограничение на публикацию планировок? Поэтажный план объекта с трассами
  слаботочки — это, возможно, чувствительная информация для заказчика.
