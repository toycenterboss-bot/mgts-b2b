Отчёт, не превратившийся в строку с номером и числом, остаётся мнением.

## Чем это отличается от «посмотрел и написал»

Суждение без прибора превращается в «стало лучше» — это **К-05** каталога
(`memory-bank/patterns/catalog.md`). Поэтому под каждым отчётом лежит число,
снятое машиной на живых страницах, и снятое **дважды**: сейчас и на стенде.
Разница чисел и есть доказательство, что дизайн улучшился.

Прибор: `mgts-frontend/scripts/design-metrics.mjs` (Playwright, реальные
вычисленные стили). Артефакты замера:

- `metrics-before.json` — 100 страниц, окно 1366×900;
- `metrics-before-mobile.json` — те же 100 страниц, окно 390×844;
- `metrics-before-light.json` — светлая тема, впервые измерена 19.08;
- `metrics-after*.json` — те же замеры после Ф1;
- `page-fill.json` — объём текста в теле каждой страницы;
- `defects.md` — реестр дефектов, машинные ворота `check-defects.mjs`.

Светлая тема измерена впервые и оказалась вдвое хуже тёмной: 6717 узлов,
включая **белый текст на белом фоне**. Её никто не мерил, потому что мерить
было нечем.

**Второй прибор — эталон геометрии** (`scripts/geometry-baseline.mjs`).
Попиксельное сравнение для темы не годится: тема меняет цвет, пиксели разойдутся
на каждой странице, и прибор закричит там, где всё правильно (**К-03**). Коробки
цвет не двигает. После Ф1: сдвинулось 1231 из 35 869, исчезло 0, появилось 0.

Повторить:

```sh
cd mgts-frontend
node scripts/design-metrics.mjs --out ../docs/design-review/metrics-after.json
node scripts/design-metrics.mjs --vw 390 --vh 844 --out ../docs/design-review/metrics-after-mobile.json
node scripts/design-metrics.mjs --gate            # ворота приёмки Ф1
node scripts/check-defects.mjs                   # ворота реестра дефектов
```

Или через npm: `design:metrics`, `design:metrics:mobile`, `design:gate`, `design:defects`.

**Ворота** (`--gate`) возвращают 1, пока показатели не уложились в пороги
(`handoff.md` §«Метрики приёмки»). Сегодня они красные по пяти строкам — это
правильное состояние до Ф1, а не поломка. Включаются явно, не по `NODE_ENV`:
приборы, которые сами решают, когда краснеть, краснеют не тогда.

| M14 | `.site-main { padding-left: 10px }` | `geometry-baseline` | 707 коробок, 5 страниц из 5 ✅ |

`check-defects` в первой редакции покрасил **все 18** ручных дефектов сразу:
`\b` в JavaScript считает словом только ASCII, поэтому после кириллической «я»
границы слова нет и шаблон не совпадал. Ложный красный ничем не лучше ложного
зелёного — он приучает не смотреть на проверку.

M2 в первой редакции остался **зелёным**: прибор считал «фокусируемым» поле
поиска в шапке, которое фокус берёт, но никуда не ведёт. Это **К-04** — молчание
принято за исправность. Прибор исправлен (считаются только ссылки и кнопки),
мутация переснята. Ошибка поймана запуском, а не чтением.

## 🔴 Границы честности

1. **Контраст меряется только на плоском фоне.** 5038 узлов из 15969 (32 %)
   пропущены: текст поверх картинки, градиента или полупрозрачного слоя. Там
   прибор молчит, а глазом может быть нечитаемо. Это **К-04**, не закрыт.
2. **Замеры сняты на dev-сервере Next.js.** Красная плашка «1 Issue» на снимках —
   служебный оверлей разработки, не элемент дизайна. Прод-сборка может отличаться
   гидратацией и размерами.
3. **Скринридером не проверялось.** Автоматика ловит ~30 % проблем доступности;
   VoiceOver/NVDA и проход только с клавиатуры руками — не делались.
4. **Отчёты — суждение**, а не измерение. Измерены только числа в таблицах.
5. **Прогон один.** Пока нет второго прогона, ни одно «стало лучше» не доказано.
6. **Один показатель плавает.** «Ошибок в консоли» дал 31, 19 и 25 на трёх
   прогонах одной и той же базы: ошибки гидратации зависят от таймингов. Остальные
   тринадцать показателей от прогона к прогону совпали до единицы — проверено
   повторным замером 19.08.
